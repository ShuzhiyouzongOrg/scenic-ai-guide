# 地图与 AI 导游交互实测

2026-11-22，隔离编译的游客端 H5，Chromium 手机视口 390 × 844；Android 运行在 MuMu 1080 × 1920、480 dpi 模拟器。H5 请求重定向到本机内存数据库的同仓测试服务。浏览器音频使用合成麦克风；暂停与继续使用受控的 8 秒 WAV 响应，以便区分播放器状态和供应商故障。

| 入口及触发步骤 | 实际结果 |
| --- | --- |
| 地图 → 筛选，输入不存在的地名，再输入“九龙” | 无结果时显示清空/更换条件提示；选择九龙灌浴后底卡和标记同名，收起保留选点，展开取消后清除选点。[浏览器选点](evidence/map-selected-390.png) |
| 筛选 → 拈花湾；模拟第一次 bootstrap 503 → 重试 | 景区标题及路线更新；重试能重新加载灵山真实测试数据与 47 个可见景点 |
| 行程 → 生成 → 首站下移 → 在地图查看 | 地图显示“2-3小时经典路线 · 顺序示意，部分站点暂无坐标”。根据 DOM 读取的标记编号，灵山大照壁为 1、五明桥为 3、菩提大道为 4、九龙灌浴为 5、梵宫为 8，与编辑后行程序列一致 |
| Android 地图 → 点击编号 4 → 取消选点 | 核实圆点、站序可见；选择后标签保持正向，底卡与标签同为“九龙灌浴”，取消后清除选中样式并收起卡片。[地图](evidence/android-map.webp) · [点位与底卡](evidence/android-map-selected.webp) |
| AI → 录音 → 取消；再开始录音 → 发送 | 首次取消未发上传；第二次检查 multipart 中 RIFF，16000 Hz、单声道、PCM16、最后一轮测试为 14400 个采样，真实本机 `/api/voice/ask-upload` 返回 200。[录音状态](evidence/ai-recording-390.png) |
| 浏览器拒绝麦克风权限 → 改发文字 | 就近说明麦克风未获授权，未触发上传；同一个输入框继续发送文字并收到回答 |
| 正在录音 → 切换到首页 → 回到 AI | 离页丢弃；总上传次数保持为一，回到 AI 显示空闲 |
| 文本提问成功 → 音频实际开始 → 暂停 → 继续 → 停止 | 页面依次显示正在播报、播报已暂停、正在播报、可提问。修正浏览器的快速暂停竞态，复测中无未处理的 play Promise 错误。[暂停状态](evidence/ai-paused-390.png) |
| 延迟 TTS 返回，在“正在准备播报”点停止，再释放旧响应 | 未请求旧音频 URL，保持空闲，已生成的回答仍可阅读 |
| 延迟第一条文字问答返回，输入另一条未发送草稿，从地图点“请导游规划游览”回到 AI | 忙碌期间仅发出第一次请求；第一条结束后自动发送一次地图问题，输入草稿仍在。另一次在等待中再次切回首页，释放首个响应时后台未发送地图问题，重新进入 AI 后准确发出一次 |
| 缺少云端数字人凭据，安全会话返回 503 | 页面显示云端不可用、静态形象和重连入口，文本与宿主音频仍可用。浏览器网络面板保留了预期的 503 记录 |

上述操作覆盖交互和浏览器音频格式。合成麦克风与模拟音频不能证明真实口音识别、讯飞云帧同步、手机声学表现。iOS、Harmony、微信宿主录音授权及真实供应商会话需用相应设备和凭据复验。项目现有的讯飞数字人宿主桥没有逐帧暂停协议；每条答案提供能暂停和继续的“语音朗读”。[状态契约](../pages/ai-guide.md) · [发布核对表](release-checklist.md)

## 微信 Live2D 画布回归

正式 AppID 的开发者工具模拟器发现，从其他标签切回标准动效后，原生形象可能只剩竖纹。同一模型冷启动可正确显示。源码核对发现组件在不可见时也只测量一次画布，零高度会按 1 个逻辑像素处理。修订后，在插槽与可见画布尺寸一致时挂载；滚动、重显和调整窗口都复用同一组模型和纹理。

| 独立检查 | 观测结果 |
| --- | --- |
| 组件生命周期测试，先隐藏，再依次回传 325 × 1、325 × 190 | 隐藏时零挂载，拒绝高度为 1 的读数，正确尺寸到达后仅挂载一次 |
| 隐藏后将区域改为 240 × 210，再次显示，随后卸载并交付过期的测量回调 | 已有运行时恢复并重设缓冲区，未加载第二份模型。卸载后的回调没有重启绘制 |
| 将项目原生运行时接入 Chromium WebGL，读入原模型服务提供的 Haru 模型、动作和纹理，设备像素比设为 3 | 实际绘制后上报 CSS 325 × 190、绘制缓冲区 975 × 570。独立截图有 1,415 种 RGB 颜色，中心列有 67 种；尺寸改变后缓冲区为 720 × 630。像素统计只在测试读取截图 |
| 完整释放 Cubism，再为新画布加载相同模型 | 复现 Core 4.2.2 抛出 `Finished up all reserved function pointers`。此前错误是字符串，页面记录为笼统的“初始化失败”。适配层复用 Core 已注册的日志回调后，新画布完成真实首帧，独立截图包含 1,693 种颜色 |
| 将完整渲染的舞台暂停并隐藏 330 ms，再重新显示 | 观察到原生运行时安排的动画回调数保持 33，再显示后达到 36。减动模式保留静态形象，恢复时沿用已初始化的 WebGL 上下文 |

微信开发者工具对最终包走完“标准 → 个人中心开启减少动态 → AI 显示立绘 → 个人中心恢复标准 → 返回 AI”。末次截图的页头显示“Live2D ready · Guide voice”，角色面部与衣着清晰可见，两次标准模式截图中的手臂姿势不同。此路径此前会回退到不可用状态。微信模拟器截图与其他交互结果见[微信模拟器记录](wechat-followup.md)。
