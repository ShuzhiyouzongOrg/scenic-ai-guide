# Trip · 行程规划

游客先选时长和兴趣，再检查沿途景点、停留时间与顺序，最后保存或在地图中查看。生成、编辑、保存是三个独立操作。返回标签页时应保留当前未保存结果。

| ID | 决策与原因 | 工程约定 | 验收 |
| --- | --- | --- | --- |
| TRIP-01 | 时长单选，灵山个性化推荐提供兴趣多选。选中态显示符号，低饱和度环境也能确认选择。 | 复用选择组件。灵山保留 60/180/360 分钟及五种服务端兴趣键，调用既有 recommendRoute。拈花湾从 fetchGuideRoutes 返回的官方路线中按时长最接近匹配，界面明确推荐依据。 | 比对提交体与选项；两景区返回各自路线；加载期间不能重复请求；失败仍保留已选条件，可重试。 |
| TRIP-02 | 时间线按实际游览顺序读，显示节点名称与建议停留分钟。 | 拖动限定在排序把手。未拖到的区域仍可正常滚动；另提供逐项上移/下移。拖动只在释放时提交，取消不改顺序。 | 拖第二站经过第三站，取消、再次释放；再用上下移完成同一结果。边界不能移动到列表之外。 |
| TRIP-03 | 只在服务确认后标记已保存。 | 修改顺序保留原始路线 id、节点 id 和总时长。saveRoute 提交有序 nodes，服务存有序 nodeIds；地图读取同一快照。旧存档按原 nodeIds 恢复。 | 连续点击不会创建重复保存记录。改序、保存、重开已保存行程，检查地图与时间线一致。断网保存失败仍可再次操作。 |
| TRIP-04 | 已保存记录有独立的加载、空、错误与数据状态。 | 首次加载失败保持重试入口；刷新错误保留旧行程。不能将缺失图谱节点静默画成另一条完整路线。 | 对保存列表与图谱分别模拟失败，验证仍可查看现有结果、重试恢复。 |

## 来源与适配

TRIP-01/02 采用 Apple HIG 的选择控件、拖放替代方案与直接操控原则。TRIP-03/04 以服务器 `src/services/routePlanner.mjs` 的快照格式为依据。地图线路只作顺序示意时必须明确其用途。当前持久化模型只存节点 ID，不在本页提供会在恢复时丢失的停留时长编辑。

参考 [Apple HIG Drag and drop](https://developer.apple.com/design/human-interface-guidelines/drag-and-drop) 与 [Apple HIG Motion](https://developer.apple.com/design/human-interface-guidelines/motion)。
