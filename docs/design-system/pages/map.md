# 景区地图

入口为 `visitor-app/pages/map/index.uvue`。手绘地图的像素尺寸、灵山旋转配准、地理投影和缩放边界对应真实底图；调整页面间距时应单独验证景点仍落在原位置。

| 规则 | 目的与实现 | 检查 |
| --- | --- | --- |
| MAP-01 地图优先 | 初始露出可操作地图，筛选可展开。定位、筛选、缩放、卡片句柄均有明确点击区域。展开卡片时让出筛选区域，卡片详情较长时通过详情页继续阅读 | 最小支持屏宽、横屏、挖孔屏中检查：至少有一片连续的地图可拖动，顶部操作不压住系统区域 |
| MAP-02 同一选点 | 手绘 marker 和原生 marker 共用景点 ID。标记强调、名称、卡片和“问导游”均对应同一个对象。再次选择或清除选择后收起卡片。折叠保留选点，上次拖动结束后的误触应忽略 | 搜索、点位、行程送来的景点各进入一次；核对标题、详情参数和导游提问 |
| MAP-03 搜索与失败 | 搜索匹配名称、别称和分类，范围限于当前景区的景点。无结果显示清空条件，网络失败提供当前范围的重试。切景区后不得把旧数据标成新景区；通过请求序号忽略过期结果 | 快速切区、断网、输入不存在的关键词、清空、重新选择 |
| MAP-04 路线顺序 | 未编辑的路线尽量使用服务端的 polyline。经过调整的行程按有序 nodes 在当前景区匹配地点并编号，以顺序连线示意。跨景区或无法解析的点不可随意拼接成步行路径 | 打开官方路线，交换中间两站后由行程页进入地图，再切回官方路线，核对编号、线段、说明 |
| MAP-05 手势 | App 在自绘区域处理平移/双指缩放；其他支持端用 movable-area/view；原生地图把手势交给 SDK。不要在每个 touchmove 中发请求或重建点位。缩放按钮为单指替代操作 | 连续捏合后点击地标，长距离拖动后松手，切换底图，核对没有残留选择或额外动画 |
| MAP-06 图层 | 底图、路线描边、路线、普通点、选点、操作浮层、信息卡自下而上。用名称、轮廓、编号加强区分。手绘路线与原生地图使用同一选色策略 | 在两块底图亮色/深色区域各抽查三处，打开减少动态效果核对所有操作可进行 |
| MAP-07 设施深链 | 首页的服务设施也能在地图定位。详情页传递景区与设施 ID，地图临时显示一个选中设施，展开卡片后留出平移空间。取消选取时恢复当前景点筛选 | 在窄屏由首页游客中心进入详情，再进入地图。核对高亮标记、设施标题、类别、可视范围和清除前后的标记数 |
| MAP-08 语言 | 控件、已知类别、位置与网络提示随个人中心的语言切换。搜索同时接受原名、别称和当前界面的类别。景区原图、点位名、路线名和介绍使用资料原文，卡片说明来源 | 依次用 Attraction、景點、景点搜索，选同一地标，核对三种语言的详情动作和带给导游的提问 |

## 服务与平台

保留 `fetchMapGuideBootstrap`、官方路线优先级、坐标解析、GCJ-02 定位、详情和数字人导航入口。调整行程沿用 `RouteRecommendation.id` 和有序 `nodes`。操作均基于同一个页面状态；不得通过重新创建 map 组件模拟按钮反馈。定位失败展示原因并保留原有浏览位置。App 与 Web 的在线地图还取决于现有图商配置和密钥授权，质量记录中分别记录手绘和在线地图。
