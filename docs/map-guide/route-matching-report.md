# 路线融合与匹配报告

## 当前游客端策略

游客地图当前仅展示 `official` 景区官方路线。目标项目既有精选路线仍保留在迁移清单和生成数据中，现有 AI 推荐接口也未被改写，但地图页不再加载、生成或展示精选、AI、混合及用户路线。

## 官方路线几何复核

来源小程序的 `pointList` 同时承担两种用途：

- 每一项的 `routePoint` 是官方编辑的道路轨迹点，6 条路线合计 364 个顶点。
- `poiPoint` 非空的项是可讲解景点节点，合计 70 个。

网页端分别保留两套坐标：

- 官方折线始终使用完整 `routePoint` 轨迹，不再用景点之间的直线代替道路路径。
- 编号景点 Marker 优先使用已匹配景点的标准坐标，使编号与地图景点标识重合；未匹配的节点才回退到来源道路锚点。
- 原始道路锚点继续保存在节点 `coordinateSource: official-route-anchor` 字段中，供审计和路线轨迹使用，不会被删除或静默覆盖。

道路锚点与景点中心平均相差约 21～46 米，最大约 150 米。这解释了旧实现中编号点明显偏离景点的问题，并非重复坐标转换造成。

## 景点匹配规则

1. 稳定 ID。
2. 标准化名称精确匹配。
3. 别名匹配。
4. 名称与坐标联合匹配。
5. 人工审核。

官方路线 70 个节点中，66 个通过稳定 ID 关联，剩余 4 个通过标准化名称精确匹配关联；没有使用名称模糊匹配，也没有制造虚假坐标。

## 路线性质

官方路线标记为 `geometryKind: official-path`，表示景区编辑的园区路线，但仍不是实时步行导航。上线时不得宣称其具备实时绕行、无障碍路径或施工封路能力。
